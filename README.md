# Penpot for ChatGPT

[![Check](https://github.com/makesomethingshit/penpot-for-chatgpt/actions/workflows/check.yml/badge.svg)](https://github.com/makesomethingshit/penpot-for-chatgpt/actions/workflows/check.yml)

Five design skills and a desktop MCP bridge for working with your existing Penpot files. Inspect a screen, implement it in code, create a responsive variant, maintain a design system, or audit a flow.

This is an unnumbered development package. The first release will be `0.1.0` when deployed.

The skills inspect the live design first, preserve components and tokens, and verify changes with read-back and exported previews. This is an independent integration, not an official Penpot or OpenAI product.

## What you can do

| Skill | Example request |
| --- | --- |
| `penpot-use` | "List the boards on the current page without changing anything." |
| `penpot-design-to-code` | "Implement the selected screen in this project's existing frontend." |
| `penpot-generate-design` | "Create a mobile variant beside this board using the same components." |
| `penpot-design-system` | "Inspect token aliases and identify consolidation candidates." |
| `penpot-audit` | "Audit this checkout flow and show evidence for each issue." |

## Install in Codex

Requires Node.js 22+ on the desktop application's PATH, a plugin-capable Codex client, and an account on [Penpot](https://design.penpot.app/).

For users with access to this private GitHub repository:

```sh
codex plugin marketplace add git@github.com:makesomethingshit/penpot-for-chatgpt.git
codex plugin add penpot-for-chatgpt@penpot-for-chatgpt
```

Git/SSH authentication must already work on your machine. Do not copy an SSH key or GitHub token into this plugin. If you already cloned the repository, register the local checkout instead:

```sh
codex plugin marketplace add .
codex plugin add penpot-for-chatgpt@penpot-for-chatgpt
```

The checked-in bridge is ready to run; installation does not require npm or a build. Reload the client's plugin/MCP connection after installing. Desktop hosts supporting Agent Plugin archive import can use the archive generated by `npm run package` through their supported import flow.

The marketplace catalog is at `.agents/plugins/marketplace.json`; the plugin is at `plugin/`. Publishing the GitHub repository and importing it into a host are separate steps. See the [official plugin packaging guide](https://developers.openai.com/plugins/build/plugins).

### Update

For the Git-backed marketplace:

```sh
codex plugin marketplace upgrade penpot-for-chatgpt
```

For a local checkout, update that checkout before re-adding the plugin. Reload your desktop host's MCP connection. Your connection file lives outside the plugin and does not need to be re-entered unless the Penpot key changed.

Codex may assign its own cache version when a development manifest omits `version`. That internal label is not this project's release number; use the Git commit to identify development builds.

### Download a verified package

Open a successful [Check workflow run](https://github.com/makesomethingshit/penpot-for-chatgpt/actions/workflows/check.yml) for the commit you want and download its `penpot-plugin` artifact. Extract GitHub's artifact ZIP to obtain the standalone `.tar.gz` and `SHA256SUMS`. Artifacts expire after 14 days and require access to this private repository. Build locally if the artifact has expired.

## Connect your Penpot account

Enable MCP under **Your account > Integrations > MCP Server** and copy the full server URL. Open a design file and choose **File > MCP Server > Connect**. Keep the browser tab awake. Follow the [official Penpot setup guide](https://help.penpot.app/mcp/) for the account and browser steps.

### Windows

From this repository directory:

```powershell
powershell.exe -NoProfile -File .\plugin\scripts\penpot-setup.ps1
```

Paste the full URL into its hidden prompt. The script checks Node.js and stores the URL encrypted with Windows DPAPI in `%USERPROFILE%\.penpot-for-chatgpt\connection.json`. It makes no network request. If execution policy blocks the script, review it and follow your organization's policy; do not change machine-wide policy for this plugin.

### macOS and Linux

Provide `PENPOT_MCP_URL` in the desktop host's process environment. For Codex launched from Bash, enter it without placing it in shell history:

```bash
read -r -s -p 'Penpot MCP URL (hidden): ' PENPOT_MCP_URL
printf '\n'
export PENPOT_MCP_URL
codex
unset PENPOT_MCP_URL
```

A GUI launched from a terminal may not inherit that environment; use your host's documented environment setup. No macOS/Linux credential-store installer is included.

### First check

Reload the desktop MCP connection and ask:

> Inspect the current Penpot page and list its boards without changing anything.

The bridge forwards official tool schemas, responses, pagination and images. It accepts the SaaS endpoint `https://design.penpot.app/mcp/stream` with your `userToken` and refuses redirects on all HTTP methods. Self-hosted endpoints are outside this release's scope. Re-run setup when your key changes.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| No tools | Node.js 22+ on the app's PATH, local credentials, and MCP startup. |
| Authentication fails | Your URL/key in Penpot Integrations; update the local configuration. |
| Connection is missing | Run the Windows setup script or set `PENPOT_MCP_URL` in the host environment. |
| Connection file is damaged | Run setup again to replace the invalid file. |
| Cannot decrypt the connection | Run setup as the Windows user that runs the desktop host. |
| Invalid MCP URL | Copy the full official URL; use exactly one non-empty `userToken`. |
| Documentation works, design calls fail | Connect MCP inside the intended file and wake its browser tab. |
| Wrong file/page | Verify the active MCP tab and focused page before requesting a change. |
| Web/mobile cannot start the bridge | Use a desktop host able to run local stdio MCP processes. |

Do not paste your URL, key or credential file into chat, issues, screenshots or source control. See [credential handling](SECURITY.md).

## Develop and verify

```sh
npm ci --ignore-scripts
npm run build
npm test
npm run check
npm run package
```

SDK and esbuild versions are pinned in `package-lock.json`. The build generates `plugin/server/bridge.mjs`, metadata and licenses for dependencies actually bundled. Tests use Node's built-in runner and synthetic credentials without contacting Penpot. They cover initialization, GET/POST redirect refusal, schemas/pagination/images, session/protocol headers, safe errors and process shutdown.

The setup script and bridge share the same URL validator. On Windows, tests run setup in a temporary user profile, round-trip DPAPI, and verify rejected input preserves the existing configuration. Settings errors distinguish missing, unreadable, damaged and undecryptable credentials without printing their contents.

`npm run check` validates manifests, five skills, local links, icons and the marketplace entry. `npm run package` writes one standalone plugin directory to `dist/penpot-for-chatgpt-preview.tar.gz` and a `SHA256SUMS` file. It allows only the required files, then reads back the archive and compares every file with the source. It excludes npm dependencies, Git data, tests and the marketplace catalog.

CI rebuilds and tests on Node.js 22 on Windows and Linux, then stores the verified Linux package as an artifact. See [CONTRIBUTING.md](CONTRIBUTING.md) for source changes and bug-report details.

## Limits and attribution

Inspection and audit stay read-only. Edits preserve unrelated boards and component/token links. Visual changes need exported previews. Design-to-code needs workspace tools, and browser comparison needs browser tools. Accessibility findings are limited to measured evidence.
